## 1. Ringkasan Eksekutif

Cerberus adalah **policy engine + enforcement stack untuk AI agent gateway** — "satpam untuk semua instance agent". Dia menjawab satu pertanyaan untuk setiap aksi agent: **"boleh?"** — dan menjawabnya konsisten via Rego policy, tercatat penuh di audit trail, dan bisa **dipaksa patuh** lewat jalur in-path (proxy), bukan cuma ditanya (SDK advisory).

### Tiga lapis pertahanan (defense in depth)

| Lapis | Mekanisme | Bisa di-skip agent? | Menjawab |
|---|---|---|---|
| **1. SDK / advisory** | SDK Go/Python/TS → `POST /v1/decide/{llm,tool}` sebelum act | ⚠️ YA (voluntary) | "Bolehkah aku?" |
| **2. Policy engine** | Engine Go + OPA/Rego embed, :8089 | — (otak keputusan) | "Apa hukumnya?" |
| **3. In-path proxy (GERBANG)** | tap :8090 (LLM), egress :8088 (HTTP keluar), socket-proxy :2377 (docker) | ❌ TIDAK — satu-satunya jalan | "TIDAK, dan tidak bisa dilewati" |

**Prinsip inti:** SDK = kesopanan, engine = hukum, proxy = tembok. Agent baik tertahan di lapis 1 (cegah kecelakaan); agent ter-inject prompt di lapis 2 (analysis isi); agent sengaja jahat di lapis 3 (tidak ada jalan lain).

## 2. Komponen & Layanan

### 2.1 `cmd/cerberus` — Engine (Otak)
- Bind `127.0.0.1:8089` (loopback only — tidak expose ke luar)
- **OPA sebagai library** (bukan sidecar service) — keputusan in-process, µs–ms
- Rego policy hot-reload via admin API — **tanpa recompile, tanpa restart**
- PostgreSQL = system of record (policies/data/audit sync), file flat sebagai fallback
- ~85k TPS sustained (loadgen `cmd/loadgen-stress`, detail docs/BENCH.md)
- Audit: SQLite rotasi harian + ring buffer in-memory + SSE stream events

### 2.2 `cmd/cerberus-tap` — LLM Gateway Interceptor (BARU 13 Nov) 🔍
Reverse proxy untuk SEMUA trafik LLM agent (Anthropic-compatible API):
- **Capture per-turn**: request (model/system/messages/tools), **SSE reassembly** (thinking_delta → thinking utuh, text_delta → jawaban utuh, input_json_delta + content_block_start → tool_use lengkap dengan nama & argumen), response + usage
- **Enforcement in-path**: flag `-engine-url` → `POST /v1/decide/llm` SEBELUM forward; verdict **deny = HTTP 403 `tap_blocked`, request tidak pernah menyentuh upstream**
- SSE di-tee transparan — client (agent) tetap menerima stream real-time tanpa latency tambahan berarti
- SQLite rotasi harian `tap-YYYYMMDD.db`, retention prune 14 hari (configurable)
- **Authorization/x-api-key diteruskan ke upstream tapi TIDAK PERNAH dipersist** — di-assert oleh unit test permanen + diverifikasi grep DB live
- Identitas pemanggil: header `X-Tap-Key` (nama agent), default `unknown`
- Endpoint internal: `/tap/healthz`, `/tap/turns?since=&key=&limit=`, `/tap/stats`
- Fail-open jika engine unreachable (visibility tetap jalan; log WARN) — keputusan sadar: v1 tidak boleh mematikan trafik LLM karena monitor mati
- Test: 5 paket `-race` clean — roundtrip non-stream, SSE reassembly, deny-blocks, retention, 20-goroutine concurrent saves

### 2.3 `cmd/cerberus-proxy` — Docker Socket-Proxy (:2377) + Egress Proxy (:8088)
**Socket-proxy:** satu-satunya pintu agent ke `docker.sock`:
- Container prod ter-shield — `stop/rm/kill` pada container protected → **403** (terverifikasi live: `stop teknikalidnew-db-1` → 403, DB tetap sehat)
- Socket di-mount read-only

**Egress proxy:** semua HTTP keluar dari agent wajib lewat sini:
- Prod CIDR / internal IP diblok (10.x → **403**, terverifikasi live; internet normal → 200)
- Host-spoofing, raw-IP bypass, header tricks → diblok (diverifikasi redteam suite)

### 2.4 `cmd/cerberus-redteam` — Attack Suite
10 serangan otomatis: 9 BLOCKED + 1 WARN + 0 EXPOSED. Termasuk host-spoof 403, raw-IP 403, key-spoof 401, burst 429×50, kill-switch holdout, prompt injection via messages[].

### 2.5 `cmd/cerberus-bundle` + `cmd/loadgen-stress`
Bundle policy signing (ed25519) + dry-run + rollback; load generator untuk benchmark TPS.

### 2.6 `owl/` — Dashboard (Next.js 15)
Login lockout 5-attempt/15m, session cookie, proxy pattern (admin token tidak pernah sampai browser). Monitoring tab (Astryx SRE pattern) dengan timeseries allow/deny + component health. *(Saat review: OWL down pasca-reboot 12 Nov, rebuild pending — bukan defect kode.)*

### 2.7 `sdk/{go,python,ts}` — SDK Advisory
Decide-call untuk agent yang baik hati: `DecideLLM()`, `DecideTool()` — budget check, model allowlist, blocked patterns, sebelum aksi dijalankan.

## 3. Deploy Topologi (LIVE 13 Nov)

```
HOST (Mac Mini, OrbStack)
├─ engine :8089  ← host process, satu sumber policy + audit (pid stabil)
└─ ~/cerberus-gate/ = compose project TERISOLASI (name: cerberus-gate)
   ├─ cerberus-tap    :8090  → engine via host.docker.internal:8089
   ├─ cerberus-proxy  :2377  → /var/run/docker.sock (ro)
   └─ cerberus-egress :8088  (listener dummy :8087 internal + egress :8088)
   Networks: sendiri · Volumes: tapdata/proxyaudit/egressaudit sendiri
   ⛔ teknikalidnew (prod teknikal.id) TIDAK tersentuh — project/network/volume berbeda total
```

**Isolasi yang diverifikasi:**
- `docker ps` teknikalidnew healthy sepanjang semua test gate
- Compose file `chmod 600` (berisi engine token), repo mount read-only
- Semua port publish `127.0.0.1:` — tidak ada expose publik
- `restart: unless-stopped` + OrbStack auto-start = self-healing pasca-reboot

**Pitfall operasional tercatat:** go.mod minta go ≥1.25 (image golang:1.24 gagal `GOTOOLCHAIN=local`); egress flag `-listen` dan `-egress-addr` tidak boleh sama port (dua listener bentrok).

## 4. API Surface (Engine :8089)

**Decide (jantung):**
- `POST /v1/decide` — generic (ssh host/user/port TOP-LEVEL; key_id WAJIB di body)
- `POST /v1/decide/llm` — prompt + messages[] + tools ke rego (gap injection di messages[] sudah ditutup, commit 280c43f)
- `POST /v1/decide/tool` — tool call permission

**Admin (auth Bearer CERBERUS_ADMIN_TOKEN):**
- `GET/PUT /v1/admin/data` · `GET/PUT/DELETE /v1/admin/templates` (builtin → 409)
- `POST /v1/admin/policy/validate` · `regex/test` · `reload` · `explain`
- `POST /v1/admin/bundle` (+`rollback`) — signed bundle deploy
- `POST /v1/admin/replay` — replay audit ke policy baru (sandbox)
- `GET /v1/admin/status|coverage|revisions|break-glass` (+POST/DELETE break-glass)
- `POST /v1/internal/sync` — PG sync

**Observability:**
- `GET /v1/audit` · `/v1/audit/timeseries` (bucket epoch-aligned, split allow/deny, param until)
- `GET /v1/health/components` · `/v1/events` (SSE) · `/v1/metrics` · `/v1/policies` · `/v1/status`

## 5. Policy Model

- **Rego embed** (15 file .rego): readable, testable (152/152 OPA test), hot-reload
- Struktur data: `agents` (per-key: budget, model allowlist, masking scope), `blocked_patterns`, `domains`, `prod_shield` (protected containers + CIDR), `teams`, `config` (bypass_unknown_keys=ON onboarding fail-open — key tak terdaftar di-allow + dilog; bisa dikunci saat onboarding selesai)
- **Masking**: regex redact/mask/hash, scope args/response — termasuk prompt & balasan LLM (applyPromptMasking) → IP/key di percakapan TIDAK masuk audit at-rest; audit DB di-rotasi harian
- **Kill switch**: break-glass — tahan semua keputusan deny (dengan audit trail sendiri)
- **Rate limit**: per-key token bucket (burst → 429)

## 7. Batas & Risiko yang Diketahui (jujur, untuk review)

1. **Tap fail-open saat engine down** — visibility jalan, enforcement LLM off. Trade-off sadar (monitor tidak boleh mematikan prod). Fail-closed = flag tunggal kalau owner mau lebih keras.
2. **Wiring agentd belum dilakukan** — agentd masih call LLM langsung. Gate sudah live tapi belum jadi SATU-SATUNYA jalan sampai env `AGENTD_LLM_API_BASE → 127.0.0.1:8090` + `X-Tap-Key` diset. Ini satu-satunya langkah tersisa.
3. **bypass_unknown_keys=ON** — key tak dikenal di-allow (mode onboarding). Key agentd harus diregister + flag dinilai ulang.
4. **Engine single-host** — tidak HA; kegagalan host = enforcement advisory-only sampai hidup lagi (tap fail-open menutup visibilitas tapi bukan enforcement).
5. **OWL dashboard down** pasca-reboot 12 Nov (rebuild dari repo, bukan defect).
6. **Audit 6,9jt event era 11 Nov hilang** bersama volume lama (keputusan migrasi, tercatat).
7. **Tap capture 2MB cap** — body prompt ekstrem besar terpotong (marker `_truncated`).

## 8. Rekomendasi Review (untuk Argon nilai)

1. **Prioritas tertinggi: wiring agentd → tap** (tutup gap #2 di atas) — tanpa ini enforcement LLM bersifat opsional bagi agent yang belum diarahkan.
2. Kunci `bypass_unknown_keys` setelah semua key ter-register → ganti fail-open jadi fail-closed untuk key asing.
3. Pertimbangkan `-strict` flag di tap (fail-closed saat engine unreachable) untuk jalur prod-sensitif.
4. Tambah tap → audit trail engine event khusus `stage: tap.capture` biar thinking history searchable dari Owl.
5. Unit test untuk egress listener-dummy pattern (dokumentasikan pitfall port bentrok di DEPLOY.md).
6. Rotasi manual `CERBERUS_ADMIN_TOKEN` (pernah muncul di compose env — file 600 tapi rotasi tetap best practice).
